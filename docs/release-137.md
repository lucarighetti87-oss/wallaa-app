# Wallaa 4.0.137 (137): Sentinel presence and energy

The universal 30-second high-accuracy GPS request has been removed. Foreground role discovery runs every minute without requesting location on ordinary accounts. iOS Sentinel positioning belongs to the native service rather than the JavaScript screen lifecycle. Browser-only available Sentinels use a bounded moderate-accuracy request when no cached position exists.

The existing Always-authorized native Sentinel location service retains 100 m desired accuracy and a 50 m movement filter; emergency tracking retains best accuracy. A coalescible 60-second native tick sends contact independently of movement. If a recent fix is missing, a moderate-accuracy one-shot request is capped at one per 120 seconds. Network attempts are capped at one per 60 seconds including failures; each background upload has a bounded background task. Offline/unverified/permission changes stop the tick. Source timestamps are included; stale coordinates are never refreshed by receive time. iOS controls background execution: a DispatchSource timer cannot wake a suspended or force-quit app, so physical idle/background validation is essential, and presence must remain explicitly unconfirmed when evidence expires.

Backend 4.0.85 retains contact time separately from GPS capture time and rejects malformed/future fixes. Older fixes cannot overwrite newer heartbeat fixes. The map exposes available versus last-known, stale direction-only references (at most 24 hours), reports missing-position/offline/busy counts, and never publishes stale coordinates or distance even during SOS. Explicit offline/disabled/unverified accounts expose no marker. Stale and available markers cannot merge into one available cluster. Admin operational availability also requires recent phone contact and GPS.

SOS dispatch freshness and matching rules are unchanged. Stale map references are not a promise that a Sentinel can intervene. No contract, purchase or paid Sentinel changes.

Validation: 81 app unit tests, 85 backend tests including PostgreSQL real routes, Swift harnesses exercising actual native heartbeat/tick functions (rate limits, GPS timestamp, failure backoff, permission/opt-out cancellation), existing native location/protocol/accessory/config/reminder/morning harnesses, WebKit map checks and signed Release archive. Complete WebKit CI is checked before merge. No live SOS or forced installation on another person's phone. Numeric battery savings and overnight reliability require physical measurement; no percent reduction is asserted.
