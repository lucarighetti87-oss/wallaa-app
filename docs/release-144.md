# Build 144 — Sentinel presence and on-demand refresh

- Location configuration starts independently of WB-001 authorization/migration. Scene foreground/background events reach the native service. Late accessory authorization releases bootstrap when the expected accessory becomes authorized.
- Explicitly available Sentinels retain a background activity session while authorized Always. Ordinary tracking uses moderate accuracy; a dedicated self-stopping manager obtains a stationary fix at most every two minutes. The previously shared continuous manager ignored these one-shot requests, leaving contact fresh but GPS stale. Position timestamps remain the actual acquisition time.
- Sentinel refresh/request pushes enter a bounded native precision burst. Concurrent wakes coalesce, repeats have a minute cooldown, completion waits for heartbeat acknowledgment, and the precision burst ends within 25 seconds. No permission request or opt-in occurs from a push. Active server-confirmed interventions use precise tracking, returning to ordinary tracking when status changes.
- Timestamp-only configuration writes do not restart native work. Diagnostics record state transitions without location coordinates or credentials and are excluded from Release builds.
- One fresh verified available local Sentinel moves the qualitative meter to 40% (2/5). Gray historical references do not raise it. No visible counts added.

Backend 4.0.88 complements the native change with bounded silent refreshes before matching. Physical delivery of APNs is not guaranteed by iOS. No real SOS was sent during verification.

Physical diagnosis on Luca's iPhone: the installed baseline was 142; Always permission was granted, but Sentinel was initially offline. After user activation, contact heartbeats continued with screen locked while the GPS fix aged and was omitted. A subsequent pass exposed HTTP 400 responses: the Live Protection snapshot wrote fractional native GPS accuracy into its integer column, rejecting the whole heartbeat. The same failure was reproduced in the PostgreSQL release test. Backend 4.0.88 rounds only the integer live-snapshot accuracy (consistent with other snapshot routes), while preserving original Sentinel accuracy and capture time. A successful physical pass requires deploying that backend fix first. Battery improvement is not quantified by this short test.
